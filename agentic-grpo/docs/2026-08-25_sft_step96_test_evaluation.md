# Qwen3-4B-Instruct-2507 LoRA step96：Retail test 四轮评测总结

日期：2026-08-25

## 1. 评测对象与统计口径

- 基座模型：`Qwen/Qwen3-4B-Instruct-2507`
- SFT 权重：LoRA `step_00000096`
- vLLM served model：`retail-sft-step96`
- 测试集：Retail test split，共 40 个 task
- 每个 task：4 条 rollout，共 160 条轨迹
- Agent 采样：`temperature=0.7`、`top_p=0.8`、`top_k=20`、`max_tokens=2048`
- 工具调用：`parallel_tool_calls=false`
- 用户模拟器：`openai/deepseek-v4-flash`，`temperature=0.0`
- seed：300（四轮实际 seed 由 Tau2 派生）
- vLLM 最大上下文：32768
- 原始结果：`training/data/eval/results.json`

原始文件包含 159 条有奖励轨迹和 1 条无奖励的基础设施失败：

```text
task_id=65, trial=3, termination_reason=infrastructure_error
```

本报告按项目当前决定采用保守统计口径：将该基础设施失败视为奖励 0。因此报告中的 121/160 包含一次非模型原因的失败。后续如果补跑该轨迹，应同时保留本报告，避免无记录地覆盖统计口径。

## 2. Pass^1 至 Pass^4

Tau2 的定义为：

```text
Pass^k(task) = C(success_count, k) / C(4, k)
```

它表示从同一 task 的 4 条 rollout 中随机抽取 k 条时，k 条全部成功的概率。它不是“至少一条成功”的传统 `pass@k`，因此数值随 k 增大而下降。

| 指标 | 结果 |
|---|---:|
| 成功轨迹 | 121/160 |
| 失败轨迹 | 39/160 |
| Pass^1 | **75.625%** |
| Pass^2 | **62.917%** |
| Pass^3 | **55.625%** |
| Pass^4 | **50.000%** |

四个独立 trial 的成功率为：

| Trial | 成功数 | 正确率 |
|---:|---:|---:|
| 0 | 29/40 | 72.5% |
| 1 | 28/40 | 70.0% |
| 2 | 32/40 | 80.0% |
| 3 | 32/40 | 80.0% |

四轮之间存在约 10 个百分点波动，说明单轮 40 题结果仍有明显采样噪声；四轮聚合的 Pass^1 更适合作为主结果。

## 4. 组内奖励与 GRPO 信号

| Group 类型 | 任务数 | 比例 | 对二值奖励 GRPO 的直接信号 |
|---|---:|---:|---|
| 全失败（0/4） | 1 | 2.5% | 组内方差为 0 |
| 成败混合（1/4 至 3/4） | 19 | 47.5% | 有组内相对优势信号 |
| 全成功（4/4） | 20 | 50.0% | 组内方差为 0 |

- 零方差 task：21/40，52.5%。
- 有组内差异 task：19/40，47.5%。
- 平均 task 奖励方差：0.0953125。

尽管总体 Pass^1 已达到 75.625%，仍有接近一半的测试任务表现为混合成功组，因此“高平均奖励必然导致 GRPO 完全没有信号”的判断并不成立。但 test split 只能用于最终报告，不能直接用于强化学习采样或难题筛选。正式 GRPO 前必须在 training split 上重新采样并统计对应的组内奖励分布。

## 5. 与四轮基线比较

历史基线使用相同的 40 个 test tasks、4 trials、seed、Agent 采样参数、DeepSeek 用户模拟器和 32K vLLM 上下文。

| 模型 | Pass^1 | Pass^2 | Pass^3 | Pass^4 |
|---|---:|---:|---:|---:|
| Qwen3-4B 普通版 | 39.375% | 24.167% | 16.875% | 12.500% |
| Qwen3-4B-Instruct-2507 | 51.875% | 36.250% | 28.750% | 25.000% |
| Instruct-2507 + SFT LoRA step96 | **75.625%** | **62.917%** | **55.625%** | **50.000%** |

相对 Instruct-2507 基线，SFT step96 的绝对提升为：

| 指标 | 绝对提升 |
|---|---:|
| Pass^1 | +23.750 个百分点 |
| Pass^2 | +26.667 个百分点 |
| Pass^3 | +26.875 个百分点 |
| Pass^4 | +25.000 个百分点 |

SFT 不仅提高了单条轨迹成功率，也显著增加了四轮全部成功的任务比例：全成功 task 从 10/40 增加到 20/40。

## 6. 异常与限制

终止原因统计：

| 终止原因 | 数量 | 处理方式 |
|---|---:|---|
| `user_stop` | 158 | 由环境奖励判断成功或失败，不能仅凭名称认定失败 |
| `too_many_errors` | 1 | task 68 / trial 1，奖励 0，作为模型失败保留 |
| `infrastructure_error` | 1 | task 65 / trial 3，按本报告口径保守记为 0 |

主要限制：

1. 将基础设施失败记为 0 会轻微低估模型能力；严格评测应补跑该轨迹。
2. 用户模拟器来自外部 API，endpoint 路由故障可能造成采样中断；GRPO rollout 层需要持久化、重试和按 group 补采。
3. test split 已用于本次最终报告，后续不能根据 test 结果选择 checkpoint、训练任务或奖励方案。
4. 47.5% 的混合组只说明测试分布仍有随机成败边界，不等于 training split 会有相同的 GRPO 有效组比例。

## 7. 阶段性结论

1. LoRA step96 在四轮 Retail test 上取得保守 Pass^1 75.625%，明显优于 51.875% 的 Instruct 基线。
2. Pass^4 从 25.0% 提升到 50.0%，表明提升并非只来自偶发成功，跨 rollout 稳定性也增强。
3. 19/40 个 task 仍有组内奖励差异，强化学习具备潜在信号，但应在 training split 上重新验证。
4. 下一阶段应先搭建可恢复的 rollout 数据层，再决定 vanilla GRPO、困难任务采样或过程奖励方案；外部 API 错误不得在训练中直接当作奖励 0。
